# Project Rules & Customization: ShutdownTimerPro

## 📌 Обязательные правила разработки, тестирования и безопасности

1. **🚫 КАТЕГОРИЧЕСКИЙ ЗАПРЕТ НА РЕАЛЬНЫЕ ОС-КОМАНДЫ В ТЕСТАХ (Safety & Mock Isolation)**:
   - **Строжайшее правило**: Любые автоматические тесты (`unittest`, `pytest`), тестовые скрипты и проверочные прогоны **КАТЕГОРИЧЕСКИ ЗАПРЕЩАЮТ** выполнение реальных команд питания ОС (`shutdown`, `restart`, `sleep`, `lock`, `SendMessage SC_MONITORPOWER`, `SetSuspendState`).
   - Все системные функции в модулях тестирования обязаны быть изолированы через `mock`, фиктивные заглушки (`unittest.mock.patch`) или глобальный флаг `PowerManager.DRY_RUN = True`.
   - Тесты ни при каких обстоятельствах не должны нарушать работу компьютера пользователя, закрывать сессии, перезагружать систему или прерывать работу агента.

2. **Декларация Скилов и Субагентов в Плане**:
   - При составлении любого плана реализации (`implementation_plan.md`, пре-экшн планов и архитектурных предложений) агент **ОБЯЗАН** явно указывать отдельным блоком:
     - **Используемые Скилы (Skills)**: Список специализированных навыков из каталога (например, `clean-code`, `senior-architect`, `frontend-design`, `debugger`) с кратким обоснованием выбора.
     - **Используемые Субагенты (Subagents)**: Список делегируемых субагентов (например, `research` на модели `flash`, `self` на модели `pro`) и их зоны ответственности.

3. **Единый источник правды для таймеров**:
   - Вся логика времени, обратного отсчета, отмены и синхронизации с Windows OS (`shutdown.exe`) должна управляться исключительно бэкенд-ядром. Frontend является реактивным отображением (HUD).

4. **Соблюдение политики No Silent Failures**:
   - Запрещены пустые блоки `try/except: pass` и `catch(e){}`. Любая перехваченная ошибка должна быть зарегистрирована в `app.log` и/или отображена пользователю через UI Toast.
